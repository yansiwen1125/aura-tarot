# Aura 详细产品需求文档

版本：2.0.0-preview.21 · 整理日期：2026-10-23

本文依据当前交付代码整理，区分现有行为与后续需求，取代旧版设计稿中互相覆盖的阶段性描述。验收条件表示应检查的行为，实际执行结果见 DELIVERY.md。

## 1. 目标与用户

目标：完成“提问—理解—抽牌—解读—追问—回看”的连续体验，让输出回应用户的具体情境。主要用户包括面临职业选择、关系困惑、日常情绪压力的用户，以及希望理解塔罗象征的初学者。

产品不以预测准确率作为承诺，不将内部模型审核评分展示为现实事件的概率。

## 3. 页面和导航

保留当前首页、聊天、抽牌、分析、解读、历史和对话框布局。首页主题卡沿用对应头像及主题文案，Queen / Magician 保持现有交互。未开放入口沿用原状态，整理过程不新增页面或改动导航。

视觉基线 393×852，需在 360、393、430px 宽度验证页面无整体横向溢出，抽牌横向拖动仍可用。

## 4. 提问和同意

- 用户输入非空问题；提交后立即呈现用户消息和等待状态，避免重复发送。
- 最新输入限制 500 字符，冻结问题限制 1,000 字符。
- 首次发送前展示必要上下文将交给 AI 处理的说明；确认版本由程序维护。
- 取消确认保留输入，不发出生成请求。
- 不要求用户必须抽牌，可以持续聊天。
- 引导可提出一次主动澄清，不能靠连续澄清阻止用户进入探索。
- 英文界面保留原样；回复跟随最新用户语言或明确语言要求。

## 5. 抽牌

- 运行牌组固定为 22 张大阿卡纳，每次抽取三张不同牌。
- 牌位顺序为 Past、Now、Future；正逆位由程序产生。
- 抽牌前显示并允许编辑本次探索的问题。
- 第三张选满后自动分析，无新增确认步骤。
- 问题、牌 ID、牌位、正逆位保存到会话，重试和追问不改变牌阵。
- Future 表示可反思的可能方向，不承诺确定事件。
- 抽牌画布和牌堆保持一致坐标，保留横向拖牌及当前视觉效果。

## 6. 解读

用户可见主体顺序：信息总结 → 三张牌的分别解答 → 行动建议。每张牌结合具体问题作答，避免重复牌义定义。建议控制在 1–2 项，保留提醒、推荐追问及依据展开。

内部结构保留 summary、understanding、cards、synthesis、uncertainties、challenges、actions、followups。旧存档中的三项行动仍可读取，新生成行动最多两项。

输出需满足：

- 三张牌的身份、方向及牌位与程序记录完全一致。
- 用户事实有原始消息引文，牌义有对应 meaningId。
- 总结回应真实问题，不臆造经历、情绪、技能或第三方想法。
- 解读经结构校验和模型审核后完整展示，等待期间显示阶段状态。
- 有限 Markdown 加粗按现有安全渲染处理，不执行模型 HTML。
- 失败保留原问题、牌阵和已有结果，可按现有入口重试。

## 7. 追问及重新生成

推荐追问恰好三条，应是用户可直接发送的完整问题，与最新讨论相关。自由输入和推荐追问共享会话背景，不重新抽牌。

用户纠正优先于此前描述。重新生成沿用对应请求输入，成功后替换目标回复；失败保留旧回复。重新解读保留牌阵，并纳入当前补充。切换会话后，旧响应不能写入新会话。

## 8. 请求和回退状态

| 状态 / 异常 | 行为 |
| --- | --- |
| 等待生成 | 显示真实任务阶段，不伪造完成百分比 |
| 普通聊天 | 展示实际网络增量 |
| 解读 / 追问 | 审核后展示完整结果 |
| 主动停止 | 取消请求，已输出部分按现有交互保留 |
| 未配置 / 授权失效 / 连接故障 | 气泡提示后使用本地演示；下一次仍尝试 AI |
| 主动取消 / 质量审核失败 | 不用演示回退掩盖 |
| 达到上下文上限 | 保留背景，提示开启新探索 |
| 刷新中断 | 恢复已保存内容，不自动重发付费请求 |

演示回复必须可辨识，不将等待中的正常 AI 请求误标为演示。

## 9. 历史和数据

会话保存到浏览器 localStorage；保留原有最多 30 条归档和当前会话机制。v2 存储外壳读取旧版数据，旧内容不自动上传或重新生成。清空只影响相应本地记录，不等同于删除供应商曾处理的数据。

无跨设备同步，无跨会话自动长期记忆。服务端密钥不能出现在前端或仓库；必要上下文通过服务端代理发送。

## 10. 工程与服务要求

单机 Node 服务，同源访问，单次请求体最多 64 KiB。最多 40 条消息、总文本 20,000 字符。后端全局并发 1，每分钟最多 10 个已接纳请求。生成工作流最多 5 次上游调用，共用默认 180 秒超时与每日 token 预算。

所有生成统一以 Aura SSE 事件信封传输；只有普通聊天直接传输上游文本增量。密钥、后端代码和文档不通过静态服务器开放。

## 12. 质量评测与后续

后续人工质量集应覆盖五主题、中英文、否定句、假设、纠正、第三方心理、空背景和连续追问；检查事实忠实、牌义一致、相关性及行动可用性。内部审核通过不等于人工验收通过。

本次交付不宣称跨主题真实模型质量、P95 延迟或上线稳定性已经验收。后续依次补齐质量集、22 张牌义人工审阅、模型账户验证，再评估 78 张牌接入与公网访问能力。
