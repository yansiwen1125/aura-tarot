# AI 解读工作流

本文说明当前代码中的固定工作流，不引用早期未实施架构作为已交付能力。

## 输入与信任边界

输入由当前会话快照组成：主题、角色、问题、冻结问题、消息、固定牌阵与原报告。服务端校验边界，按 cardId 和 reversed 从本地 catalog 获取牌义。用户、历史回复和审核建议均作为数据，不能覆盖固定规则。

## 任务路径

| 任务 | 路径 |
| --- | --- |
| chat | 直接流式对话，不能虚构未抽出的牌 |
| guide | 事实提取 → 引导结构校验，返回文本和 nextAction |
| reading | 事实提取 → 详细解读 → 硬校验 → 独立审核 |
| followup | 事实提取 → 固定牌阵追问 → 结构与语言校验 → 审核 |

事实提取可以触发现实安全支持路由，暂停常规牌面解释。正常详细解读最多一次修订，修订后重新校验和审核，总调用最多五次。

## 事实与牌义

事实引用包含 id、messageId、quote、statement。程序确认消息确实来自用户、引文逐字存在、引用 ID 不重复。引文存在只证明来源，语义忠实仍需审核与人工评测。

每张牌必须保持 cardId、position、reversed 与快照一致，并引用正确的 meaningId。综合部分至少引用两张牌的意义。当前 catalog 是基础反思文案，不宣称专家知识库或已完成全面人工审核。

## 生成结构

summary 回答当前问题；cards 的三段分别联系牌位与真实处境；actions 给出 1–2 项具体建议。understanding、synthesis 等保留作内部结构与依据，不把它们全部堆入用户正文。推荐追问恰好三个，需是用户可直接发送、与最新问题相关的完整问句。

输出规则要求区分事实、象征和假设，不由牌面证明职业能力、历史经历、他人内心或未来结局。语言跟随最新用户输入，并检查混用与残留原文。

## 审核门槛

审核维度：fidelity 30%、meaning 25%、relevance 20%、depth 15%、action 10%，每项 0–4 分。通过要求 hardPass=true、issues 为空、每项至少 3 分且加权换算至少 85 分。

程序硬校验失败时，使用具体问题进入修订，不先把无效结构视为成功。候选未通过则最多定向修订一次，再做完整检查；仍失败返回 QUALITY_CHECK_FAILED，保留牌阵与重试入口。

审核是独立请求上下文，可使用相同模型，不能保证找出全部错误。分数是内部发布筛选条件，不是塔罗准确率。

## 成本和取消

每阶段先检查取消和预算，再调用适配器；整体默认 180 秒，最多五次。普通阶段与修订阶段的配置由 deepseek.mjs 决定。已知完整用量结算预留，未知或取消用量不退回。

本次整理没有执行真实 API，也没有验证供应商当前模型可用性或重新评测生成质量。后续需针对账户、语言和主题准备固定质量集并人工审阅。
